# The Babel Echo guard (Sermon §5)

## Placement in the master docs

Narrative paper **B1.8** — Sermon §5 Babel Echo guard (v0.5 rename). ## Summary

A **parallel relay** is exactly where the **Babel Echo** can form: silicon repeating silicon. The guard keeps each agent’s contribution **attributed**, keeps **carbon’s wordless veto** supreme, and refuses to treat **agreement as verification**. v0.5 locks vocabulary: flattery = **Honeyed Lips**; confusion about whose voice speaks = **voice confusion**; the multi-agent false consensus risk = **Babel Echo**. Handoff logs exist so attribution survives relays.

## Verbatim excerpt

From *Sermon Charter* v0.5 §5:

> **The Babel Echo guard.** A parallel relay is exactly where the Babel Echo can form (Section 4): silicon repeating silicon. So each agent's contribution stays attributed (see the fleet provenance block (internal), whose v2 adds the handoff log), and carbon's wordless veto still wins. Agents agreeing with each other is not verification. *(v0.5: "echo" now has one meaning here; flattery is Honeyed Lips, and confusion about whose voice is speaking is voice confusion. See the glossary in IPG Manifesto v1.8, Section II.)*
